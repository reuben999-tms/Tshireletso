How it works

Hashing, salting, lockouts and shutdown in plain words.

      What the gate does

      1. It builds a password with the browser’s secure random generator.
      2. It keeps only a salted PBKDF2 hash, never the password itself.
      3. Each login guess is hashed the same way and compared with the stored hash.
      4. Failures are logged. Every 3rd one locks the gate, and the 9th halts the system.

      Why it works

      A computer can try thousands of guesses a second. Lockouts cut that to a handful a minute, so a quick attack becomes one that takes years.

      Where it falls short

      Halting everything lets anyone take the system offline by failing on purpose. Real systems lock one account, add delays and alert the owner. This demo also counts failures in your browser, where a real gate would count them on a server.

      What the Trail teaches

      Check the sender’s domain, distrust urgency, never give a password by email, and never use a birthday as a passcode. Test only systems you have written permission to test.
